# 面向 CCF A 主会的研究升级路线与 V8 验证协议

## 研究定位
当前论文是单任务三个开发状态的探索记录。不能仅靠润色或补引用达到主会标准。下一研究问题是：短期几何评分能否在独立任务上优于相同候选池中的随机选择，其排序错误是否具有可重复的条件？这是一条诊断与评估研究路线，不要求先实现 LoRA；也不保证录用。若发现仅为常见采样现象而无更深规律，需重新判断贡献。

## 已有、验证、最终测试分离
- 已有 task 0 / init 0,1,2 全部属于开发，不再当独立测试。
- V8 验证试点只允许 LIBERO-Spatial task 1、2，各 init 0、1。只用来检查跨任务可行性、运行预算与分析方法。
- 候选最终测试域暂留 task 3–9。不能先看结果再选任务/阈值。真正启动最终测试前，应按验证试点的成本另行提交不可混用的任务/状态/种子清单与主要终点；当前尚未完成正式测试预注册，也没有证明该规模足够。
- 当前单 checkpoint 结果不能直接推广到所有 VLA；若发现有价值规律，再考虑第二 checkpoint/模型作为外部验证。

## V8 试点固定配置
保持已跑通的 T4/8-bit OpenVLA Spatial checkpoint、220 policy steps、10 settle steps。候选两组：原配置 T=.7,p=.95,k=50；不截断 T=1.5,p=1,k=0。每组 seeds 8–11，各四次采样，加共享贪心参考；每个状态至多九个不同实际动作。候选差异来自联合改配置，不能单独归因 top-p、top-k 或温度。

所有不同候选均运行到成功或220步，固定贪心继续策略。一次完整轨迹同时记录 H=12,24,48 的几何评分，无须重跑三种 horizon；提前成功后以吸收终止状态的终止 potential 填充后续 H，规则明确记录。H=12 为主要评分，24/48 是预定次要分析，不根据结果挑最有利 horizon。

每状态另做一次独立基线回放；完整动作轨迹与 H-potential 不一致则停止。相同动作的重复样本共享确定性评估，但随机选择的期望保留重复质量，不能按去重后的动作均匀加权。

## 要比较的对象及指标
1. 冻结贪心参考。
2. 同一组五个名义条目（基线+四次样本）均匀随机选择的有限池期望。
3. 同池 H=12 几何评分最高的候选；完全相同时优先基线，再按采样顺序。
4. 全回合结果已知后的池内最佳，仅作 privileged hindsight reference，不能充当可部署对照。

主要描述量：评分选择的成功与同池随机期望成功之差。次要量：对基线的改善/退化、评分与完整结果的排序关系、utility regret、候选集中程度。utility 定义为 success - .1 * executed_steps / 220；这是预定资源惩罚型效用，不能把失败220步当成真实完成时间。

每个状态是一个配对分析单元；候选不是独立测试样本。最终统计推断须按任务分组设计，不能用四个验证状态做显著性宣传。验收应以全部完成且通过回放的状态为单位；任何缺失、错误和预算截断均列出，不静默丢弃。当前未实现 learned verifier、门控或参数适应，不能使用这些方法的名字作为实验完成标记。

## 算力预算与分批运行
历史两个 full-horizon 包：159步/599秒，533步/1406秒。按含加载开销的2.6–3.8秒/步粗略外推：
- 单状态至多九个独立动作+一次重复，最多2200步，约1.6–2.3小时。
- 四个验证状态至多8800步，约6.4–9.3小时。
这是粗估而非运行承诺，早停、重复率、模型下载、环境和硬件会显著改变耗时。不要据此直接购买固定时长算力。

V8 默认每次最多执行两个新分支，第一批通常是基线和重复，后续使用同目录 --resume。已完成分支不重跑；中断的单分支从头重放。跨 Colab 会话必须先备份/恢复整个运行目录；仅下载 ZIP 不会让下个运行时自动恢复。重新生成的候选、代码版本、依赖冻结和远程模型代码哈希不一致时，禁止续跑。

本入口不自动挂载 Drive、不购买算力，也未在 GPU 上运行。算力来源确定后再制作与该环境匹配的固定版本启动器。暂不要求用户重新运行 V7。

## 命令
已安装仓库及既有 LIBERO/OpenVLA 环境后：

```bash
python scripts/run_ranking_audit_v8.py --libero-root /content/LIBERO-8f1084e3132a --run-dir /content/v8-task1-init0 --task-id 1 --init-state-id 0 --max-new-branches 2
```

续跑同一固定代码版本时添加 `--resume`，其他参数不变。第一批返回 paused_branch_budget 属于计划暂停，不代表全部实验完成。只有 validation_case_complete 才生成完整池汇总。

## 阶段决策
先完成一个新状态的运行完整性检查，再完成四状态验证。若短期评分没有优于随机或存在明显退化，应如实报告并研究排序失效，而不是继续宣传有效性。若具有稳定规律，再设计补充机制、独立测试和必要外部模型验证。达到主会水平需要贡献深度与证据共同成立，不以论文页数、公式数或图表数判定。
