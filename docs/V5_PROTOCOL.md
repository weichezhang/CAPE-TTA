# V5：反事实候选短 rollout 可行性研究

状态：实验方案与代码就绪，尚未在 GPU 上执行。属于开发研究，非论文主表。

固定 Spatial/task 0，init=0,1,2；horizon=12，settle=10；
同一个已验证的 OpenVLA checkpoint、T4 8-bit/FP16。
沿用 V4 的全部四组设置，不根据新结果只保留某一温度。
每组 4 次采样（seed=8,9,10,11）加 1 个贪心基线，共 5 个名义候选。
这与 V3 的总 K=4 不同，不能将两次结果当作相同预算的正式对照。

从同一 initial state 的同一 settled observation 生成候选。
每个不同的实际执行动作在独立 fresh environment 中执行第一动作，
剩余 horizon-1 步使用相同冻结贪心策略；不做参数更新。
同一初始状态内完全相同的执行动作只 rollout 一次，记录缓存映射并保留重复采样。
基线额外独立重复一次；一致性检查失败即标记该运行失败。

保存原始动作、token、采样设置、轨迹、最终状态与进展；每个分支完成后写盘。
发生错误保留已经完成的状态和分支；失败不计作无效候选或普通任务失败。

报告每组独立动作数、相对基线的软进展差值（最佳与均值）、优于/劣于基线
的采样数，以及短 horizon 内的稀疏成功。Oracle 显式包含基线，因此其最佳
margin 不小于零是定义导致，不能作为统计显著性或方法有效性的证明。
多个候选分支不作为独立 task/init 样本；三个初始状态也不足以支持跨任务结论。

若观测到改进空间，后续另行冻结完整回合协议，检查短期软进展是否与任务
成功相关，再开发部署证据/校准/适应机制。若没有改进空间，同样保留零/负结果，
检查干预位置与时域，而不是不断换 seed 挑阳性结果。

V5 没有训练、没有部署版 CAPE-TTA，没有完整回合成功率估计，
不能直接用作投稿论文“适应提高性能”的主结论。
