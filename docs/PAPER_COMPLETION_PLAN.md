# CAPE-TTA 论文完成方案

本文件是待执行协议，不是实验结果，也不是已完成方法的描述。
截至本次仓库核查，OpenVLA 主实验没有可核验的成功结果。历史基础设施
smoke 和 checkpoint 预检不能替代模型推理、完整回合评测或适应收益证据。

## 先完成的门槛

1. 使用 V3 notebook，下载一个完整运行包。
2. manifest.status 必须为 pilot_validated；检查 validation.json、原始 JSON、
   代码 SHA、模型 SHA、LIBERO SHA、GPU、依赖版本和日志。
3. 只有模型加载、wrapper parity、候选生成、fresh replay 都通过才进入可行性研究。
   日志检查通过不表示 CAPE-TTA 有效。失败运行同样保留并记录。

## 研究问题与当前边界

拟检验问题：在同一观测下生成候选动作后，能否用可获得的进展证据识别值得
接受的候选或参数更新，并减少测试时性能退化？

现有 Oracle 访问仿真内部状态和未来分支，属于 privileged evaluation。
它不能作为可部署方法，也不构成测试时参数更新。首先验证 Oracle 上限
是否存在有实际意义的改进空间；若没有，不直接扩大实验或声称方法成立。

完整 CAPE-TTA 的证据模型、更新损失、可训练参数、步长、回滚机制以及
数据来源仍需定义、实现和验证。不能将规划写成已实现算法。
8-bit 推理成功不代表同一设置下能够直接完成参数适应。

## 低算力分阶段设计（在首个成功包后冻结协议）

### A. 开发集可行性研究

初步预算方案：Spatial 的 task 0–2、init 0–4、候选 seed 7 和 17；
K=4、horizon=12、settle=10。共 30 次 pilot。
这些运行均属于开发数据，不用于正式测试或校准保证。
先做一次 pilot 测量时间和显存，再决定这份预算是否能在免费 GPU 配额内完成。
不得因为结果差而悄悄删除 task/init；技术失败记录为失败，补跑也保留原记录。

记录候选重复率、软进展差异、稀疏成功、重复回放误差、耗时。
不把 12 步软进展差异称为完整回合成功率改善。
继续条件：管线可靠，且改进空间不是仅由个别异常样本或重复候选造成。
具体最小有意义差异在查看该阶段统计前声明；结果为零或负也如实报告。

### B. 完整回合与方法实现

首先对冻结 OpenVLA 完整回合基线进行核对，遵循官方观测预处理、动作处理
及相应 suite 的回合上限。官方参考：
https://github.com/openvla/openvla/blob/main/experiments/robot/libero/run_libero_eval.py

部署方法不能读取 simulator goal state 或 Oracle future branches。
在确定学习目标之前先明确可用观测、离线训练来源及测试时允许的信息。
若只实现候选动作筛选，应把论文定位改为选择/门控方法，而非声称参数适应。

必须实现的对照：冻结模型、等算力随机候选、未经校准的证据选择、完整方法、
privileged Oracle（单列，不与部署方法混为一谈）。
如果保留 TTA 定位，还需等更新预算的未经门控适应基线，以及更新前后参数
变化和回滚日志，证明实际发生了参数更新。

### C. 校准与最终测试

模型拟合、超参数开发、校准和最终测试分开，以 task/init 组为单位划分；
同一组的不同 seed 或分支不能落在校准与测试两边。
测试划分在选模型/阈值前固定并保存；最终测试不用于反复调参。
若任务数量少，说明只支持有限任务内结论，不能包装成跨任务泛化。

若采用 conformal 方法，先明确预测目标、非一致性分数、校准单位和交换性假设；
候选选择带来的多重比较也需纳入设计。不得将分布变化下的经验覆盖率描述为
无条件的理论保证。先不预先宣称安全性或必然提升。

### D. 正式主表与消融

冻结模型版本、8-bit/FP16 设置、任务列表、初始状态、seed、候选数量和预算。
主指标为完整回合成功率；同时报告相对冻结基线的退化、耗时、显存、拒绝率。
按 task/init 配对比较，报告不确定性，不能把同一状态的候选分支视为独立样本。

消融：去校准、去门控/回滚、去反事实证据、K 和 horizon 变化。
分布变化单列结果，并说明哪些变化属于校准假设之外。
多 suite 评测必须使用匹配的 checkpoint/norm_stats，不直接复用 Spatial 模型并
将其失败算成方法退化。先估算运行成本，再确定最终覆盖范围。
